ADR（Architecture Decision Record）用于记录重要架构决策，重点不是“做了什么”，而是“为什么这样做”。

## 1. 何时需要新增 ADR

满足以下任一条件时，**必须新建 ADR**。

- 技术选型存在多个可行方案，且决策会影响至少两个模块。
- 存储、权限模型、认证方式或状态机发生变化。
- 跨服务的数据契约发生破坏性变更。
- 用新方案替代现有方案，需要保留决策理由。
- 依赖变更带来新的安全、合规或成本风险。

可逆的局部重构、不影响对外契约的实现细节调整、个人偏好或风格微调可以直接记录在变更说明中；维护开发日志的项目也可以写入 `../devlog/`。

功能变更触发 ADR 时，在对应功能文档头部的 `Related ADR` 字段填写决策编号。

## 2. 文件命名规范

```text
ADR-001-short-title.md
ADR-002-short-title.md
```

## 3. 最低内容要求

- 背景
- 决策
- 备选方案
- 影响
- 后续动作
