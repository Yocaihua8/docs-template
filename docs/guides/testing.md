## 3. 按架构能力选择关注点

以下小节是选择指南，不是同时生效的强制清单。保留当前项目对应的部分，其他内容删除或标记 `N/A`。

### 3.1 三层架构

- 表现层：重点验证参数校验、权限拦截、响应结构
- 业务层：重点验证核心业务规则、状态流转、事务边界
- 数据层：重点验证持久化正确性、迁移脚本、第三方依赖集成

### 3.2 六边形架构

- 输入端口：重点验证用例行为和业务规则
- 输出端口：重点验证契约是否完整、异常是否向核心层正确暴露
- 输入适配器：重点验证协议转换、参数映射、入口鉴权
- 输出适配器：重点验证数据库 / MQ / 第三方 API 集成是否满足端口契约

### 3.3 库 / SDK / CLI / 脚本 / 插件

- 公共 API、参数、退出码、序列化格式或扩展点保持兼容。
- 文件、环境变量、标准输入输出和宿主边界按实际验证。
- 不存在 HTTP、数据库、消息队列或 UI 时，不创建对应测试要求。

## 4. 提交前最低要求

- 所有行为改动都必须有与风险相称的回归证据；无法自动化时记录人工步骤、预期结果和未覆盖原因。
- 对外接口或 CLI / SDK 契约发生变化时，检查成功、失败与兼容性场景。
- 存在数据库或数据迁移时，验证升级与回滚；无持久化项目填 `N/A`。
- 存在 UI 时，验证主流程以及适用的加载态、空态、错误态；无 UI 项目填 `N/A`。
