# ADR-005 订单导出产物采用对象存储托管

> 状态：Accepted
> Date：2026-04-17
> Owner：张三
> Related：`../features/order-export.md`、`../BACKLOG.md`

## 1. 背景

订单导出任务由后台异步 Worker 执行，服务采用多实例容器化部署。如果将生成的 CSV/Excel 写入应用容器本地磁盘，用户后续下载请求被负载均衡转发到其他实例时会找不到文件；同时本地磁盘空间受限，需要自行编写定时清理脚本。

## 2. 决策

所有异步导出产物统一上传至对象存储（专用私有 Bucket），通过生成 7 天有效期的预签名 URL 提供前端直连下载，并由对象存储生命周期规则在 7 天后自动删除过期文件。

## 3. 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 对象存储 + 预签名 URL | 天然支持多实例、不占应用带宽、自带过期清理 | 预签名 URL 在有效期内不二次校验角色（需依赖 7 天短有效期与内部网络访问控制） | 采用 |
| 共享 NFS 挂载目录 | 实现改动小，下载可走后端权限校验 | 运维与扩容成本高，大文件并发下载占用应用实例带宽 | 放弃 |
| 同步流式导出 | 无需临时存储 | 50,000 行导出耗时超 30 秒，极易触发网关超时 | 放弃 |

## 4. 影响

- **正面影响**：多实例任意节点均可下载；应用实例保持无状态；清理逻辑零运维。
- **负面影响**：需要在对象存储侧配置 Bucket 生命周期策略；预签名 URL 泄露风险通过站内信私密下发与短有效期缓解。
