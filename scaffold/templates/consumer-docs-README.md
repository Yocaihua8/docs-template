## 1. 最小阅读顺序

按本次任务选择对应入口和章节；下表不是每次修改前的通读清单。已读取且仍适用的内容无需重复加载。

| 当前任务 | 阅读入口 |
|---|---|
| 了解项目或确认范围 | [项目背景](requirements/project-background-and-scope.md) |
| 安装、启动或环境排障 | [环境搭建](guides/setup.md) 与实际配置 |
| 修改功能 | [功能索引](features/README.md) 中对应规格及其关联文档 |
| 维护文档 | [文档风格](style-guide.md)；可选能力只查实际生成的文件 |

先以任务涉及的正式规格和当前源码核对事实；历史计划与验收记录只说明其对应范围和版本。

## 2. 核心目录

| 路径 | 用途 |
|------|------|
| `requirements/` | 项目背景、范围以及按需启用的需求文档 |
| `features/` | 功能规格索引与可复用功能模板 |
| `guides/` | 环境搭建以及按需启用的测试、发布、安全和协作文档 |

`design/`、`adr/`、`devlog/`、`plans/`、`business/` 等目录仅在项目按需引入对应文档能力时存在。

## 3. 维护规则

- 文档只描述已经确定或已经实现的事实；未落地事项写入实际启用的任务管理入口。
- 功能行为、接口、数据、权限、架构或运行方式变化时，同步更新对应已生成文档。
- 不存在的文档不应被强制引用；后续新增或删减文档能力时，可在新的临时目录生成模板并按 diff 人工合并，同步核对本索引。
- 未知信息使用 `TBD`，明确不适用的信息使用 `N/A`，不要编造项目事实。
- 若仓库包含本地文档检查脚本，提交前运行 `pwsh scripts/check-placeholders.ps1` 与 `pwsh scripts/check-doc-links.ps1`；Bash 环境使用对应 `.sh` 脚本。
- 在 Git 工作区，链接检查覆盖已跟踪文档和未忽略的新文档。占位符检查识别工作流中的 GitHub Actions 表达式。
- 若仓库启用了 GitHub 文档 CI，链接检查会立即阻断；活动文档全部填写且本地占位符检查返回 0 后，再创建空文件 `.docs-template/strict-ci` 激活 CI 的占位符阻断。不得为了变绿而提前创建或删除该标记。
